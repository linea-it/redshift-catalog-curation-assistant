Curate Schema
==============

The ``curate`` command applies explicit, local curation rules and writes a
Parquet dataset or HATS collection. It does not infer scientific choices. The
user must identify the final RA, Dec, and redshift columns, whether those
columns already exist or are generated by transformations.

Minimal Example
---------------

.. code-block:: yaml

   input_file: tests/data/raw/synthetic_redshift_catalog.csv
   output_dir: outputs/curated/synthetic.parquet
   overwrite: true

   column_selection:
     - object_id
     - ra
     - dec
     - z_spec

   coordinates:
     ra_column: ra
     dec_column: dec

   redshift:
     column: z_spec

Required Fields
---------------

``input_file`` or ``input_files``
  Source catalog path, or a list of paths that represent one logical catalog.
  Multiple inputs must have the same schema. Small raw catalogs can be curated
  directly in memory. Large inputs must already be Parquet datasets produced by
  ``prepare``.

``output_dir``
  Directory where the curated dataset and
  ``_redshift_curator_curation_manifest.json`` are written.

``coordinates.ra_column`` and ``coordinates.dec_column``
  Final RA and Dec columns to validate and keep. RA must be numeric degrees in
  ``[0, 360)``. Dec must be numeric degrees in ``(-90, 90)``.

``redshift.column``
  Final redshift column to validate and keep. Redshift must be numeric in
  ``(-0.1, 20)`` by default. Set ``redshift.allow_blueshifts: false`` to use
  ``(0, 20)`` instead. Invalid values stop curation unless
  ``redshift.invalid_policy: flag`` or ``redshift.invalid_policy: keep`` is set.

Input And Output Options
------------------------

``column_selection``
  Optional list of output columns. If absent or empty, all source columns are
  kept. If present, order is preserved. Validated RA, Dec, and redshift columns
  must be included.

``output_format``
  ``parquet`` by default. Valid values are ``parquet`` and ``hats``. HATS input
  currently requires ``output_format: hats`` so curation can remain on the
  public LSDB ``Catalog`` abstraction and write with ``Catalog.write_catalog()``.

``generated_columns_position``
  ``last`` by default. Use ``first`` to place generated columns before selected
  source columns.

``overwrite``
  Defaults to ``false``. Set ``true`` to replace an existing output directory.

``large_file_threshold_mb``
  Defaults to ``100``. Inputs smaller than the threshold are read in memory.
  Inputs at or above the threshold must be Parquet.

``output_mode``
  ``auto`` by default. ``auto`` writes one Parquet part for small inputs and
  partitioned output for large inputs. Explicit values are ``single`` and
  ``partitioned``. Large ``single`` output requires
  ``allow_large_single_output: true``.

``target_partition_size_mb``
  Target partition size used for large Parquet/Dask processing.

``persist_after_transformations``
  ``false`` by default. When ``true`` and the input is a large Parquet/Dask
  dataframe, transformed data are persisted before standard RA, Dec, redshift
  validation and output writing. This can avoid recomputing expensive
  transformations.

``part_prefix``
  Prefix for generated Parquet part filenames. Defaults to the output
  directory name.

``fits_hdu``
  FITS HDU to read when curating FITS inputs.

``column_names``
  Required for headerless whitespace inputs such as ``.dat`` and ``.idz``.

``dask_cluster``
  Optional executor configuration using the same schema as ``prepare``.

Large Input Behavior
--------------------

Small inputs are curated in memory. Large inputs must be Parquet. For large
Parquet inputs, ``curate`` uses Dask, column pushdown, partitioned output by
default, and a single aggregate computation to validate RA, Dec, and redshift
ranges.

When ``output_format: hats`` is requested for non-HATS input, small catalogs are
curated in pandas and converted with ``lsdb.from_dataframe()`` before writing
with ``Catalog.write_catalog()``. Large Parquet inputs are curated with Dask,
written to temporary Parquet, and imported with ``hats_import`` using
``file_reader: parquet``. The temporary Parquet dataset is removed after the
HATS import.

HATS Input And Output
---------------------

If ``input_file`` points to a HATS catalog or collection, ``curate`` always
creates a Dask client, opens the catalog with ``lsdb.open_catalog()``, applies
curation through public LSDB ``Catalog`` methods, and writes the result with
``Catalog.write_catalog()``. The implementation intentionally avoids private
LSDB internals such as ``._ddf``.

HATS output uses the final validated coordinate columns by default:

.. code-block:: yaml

   output_format: hats

   hats:
     catalog_name: my_curated_catalog
     hats_output_with_margin: true
     margin_threshold: 5.0

Override ``hats.ra_column`` and ``hats.dec_column`` only when the HATS spatial
index should use different final columns. Those columns must still be present
in the curated output and already be numeric degrees in the standard ranges:
RA in ``[0, 360)`` and Dec in ``(-90, 90)``.

``hats.hats_output_with_margin`` is ``true`` by default. When enabled, curated
HATS output includes a default margin cache. ``hats.margin_threshold`` defaults
to ``5.0`` arcseconds and must be greater than zero while margin output is
enabled. Set ``hats_output_with_margin: false`` to skip margin generation; in
that case any configured ``margin_threshold`` is ignored.

For HATS collection input, ``curate`` opens the collection normally when a
default margin is declared. If no default margin is available and margin output
is enabled, it looks for margin catalogs in the collection. Without an explicit
``margin_threshold``, the smallest available margin threshold is used. With an
explicit threshold, only an exact matching margin catalog is reused. If no
matching input margin can be used, ``curate`` writes the curated catalog first
and then adds a new default margin cache to the output collection.

Redshift Policy
---------------

By default, invalid redshift values stop curation:

.. code-block:: yaml

   redshift:
     column: z

The default allows blueshifts down to ``-0.1`` and validates
``-0.1 < z < 20``:

.. code-block:: yaml

   redshift:
     column: z
     allow_blueshifts: true

To reject blueshifts, use ``allow_blueshifts: false``. The standard range then
becomes ``0 < z < 20``:

.. code-block:: yaml

   redshift:
     column: z
     allow_blueshifts: false

To keep processing and map invalid values to the standard ``-1`` flag:

.. code-block:: yaml

   redshift:
     column: z
     allow_blueshifts: false
     invalid_policy: flag
     invalid_value: -1

To keep processing without changing redshift values outside the standard range:

.. code-block:: yaml

   redshift:
     column: z
     invalid_policy: keep

``keep`` still requires a numeric redshift column. If ``redshift.filters`` are
configured, values outside the standard range are removed before those filters
are applied.

To keep only rows inside a science-specific redshift window, add
``redshift.filters``. Filters are applied to the final redshift column after
standard validation and transformations. Each filter is a simple comparison
with ``op`` and numeric ``value``. Supported operators are ``<``, ``<=``,
``>``, ``>=``, ``==``, and ``!=``.

For example, keep only rows with ``z < 9``:

.. code-block:: yaml

   redshift:
     column: z
     filters:
       - op: "<"
         value: 9

Multiple filters are combined with logical AND. This keeps
``1.6 < z < 9``:

.. code-block:: yaml

   redshift:
     column: z
     filters:
       - op: ">"
         value: 1.6
       - op: "<"
         value: 9

When filters are present, rows with invalid or flagged redshift values are not
kept, even if the flag value would satisfy one comparison numerically.

Transformations
---------------

Transformations are safe, declarative operations. They run before coordinate and
redshift validation.

``add_constant_column``
  Adds a column with one constant value.

  .. code-block:: yaml

     - type: add_constant_column
       name: survey_name
       value: SDSS_DR19

``cast``
  Casts an existing column using pandas/Dask ``astype``.

  .. code-block:: yaml

     - type: cast
       column: VI_quality
       dtype: float64

``ra_hms_to_degrees``
  Converts RA from hours, minutes, and seconds to degrees.

  .. code-block:: yaml

     - type: ra_hms_to_degrees
       output_column: ra_j2000_deg
       hours: ra_j2000_h
       minutes: ra_j2000_m
       seconds: ra_j2000_s

``dec_dms_to_degrees``
  Converts Dec from degrees, arcminutes, and arcseconds to degrees while
  preserving the sign from the degree component.

  .. code-block:: yaml

     - type: dec_dms_to_degrees
       output_column: dec_j2000_deg
       degrees: dec_j2000_d
       arcminutes: dec_j2000_m
       arcseconds: dec_j2000_s

``skycoord_to_degrees``
  Uses Astropy ``SkyCoord`` to convert coordinate columns to degrees.

  .. code-block:: yaml

     - type: skycoord_to_degrees
       ra_column: OBSRA
       dec_column: OBSDEC
       output_ra_column: RA_deg
       output_dec_column: DEC_deg
       ra_unit: hourangle
       dec_unit: deg

``velocity_to_redshift``
  Converts velocity and optional velocity error in km/s to redshift using
  ``z = v / c``.

  .. code-block:: yaml

     - type: velocity_to_redshift
       velocity_column: V
       output_column: redshift
       velocity_error_column: EV
       error_output_column: redshift_err

``coalesce_redshift``
  Creates a final redshift from prioritized candidates. The first valid value in
  the configured standard redshift range is used; if none are valid,
  ``invalid_value`` is written. By default this follows
  ``redshift.allow_blueshifts``. Optionally, ``label_column`` writes the source
  label for the candidate that supplied the final redshift. If ``labels`` is not
  provided, the candidate column names are used as labels.

  .. code-block:: yaml

     - type: coalesce_redshift
       output_column: z_final
       columns:
         - z_spec
         - z_phot
       labels:
         - s
         - p
       label_column: z_source
       invalid_label: none
       invalid_value: -1

Column Pushdown
---------------

When ``column_selection`` is present, ``curate`` reads only the input columns
required to build the selected output: selected source columns, columns needed
by transformations, and source versions of the configured RA, Dec, and redshift
columns. Generated columns are not read from the input. If
``column_selection`` is absent or empty, all source columns are read and kept.
